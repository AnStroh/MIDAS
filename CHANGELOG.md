## [1.0.0] - 2026-10-01

### Added

- Both GUIs now display an unused field (`NaN` under the current mode combination) as the literal text `NaN`, grayed out, instead of a plain `0` placeholder that looked like an active value. In `octave/MIDAS_GUI.m` this also removes a latent bug: reading a field back was inferring "unused" by comparing against `MIDAS_Params()`'s own defaults rather than whichever example/preset was actually loaded, so a field that's NaN in a loaded example but not in the base defaults (or vice versa) could round-trip wrong; the field's own displayed text is now the source of truth instead.
- `octave/MIDAS_GUI.m` - an interactive front-end for `octave/`, covering the same fields, six examples, Run/Reset, Save/Load Preset, Export Data/Figures, and Manage Results as `GUI/MIDAS.m`. Built from scratch with plain `figure`/`uicontrol` rather than ported, since Octave has no App Designer, `uigridlayout`, or `uitabgroup` to build against, and can't open `.mlapp` files at all. See [`docs/gui.md`](docs/gui.md#octave-gui).
- `tests/` - a cross-implementation consistency check: runs the same six examples through `matlab/`, `GUI/`, and `octave/` and diffs the full result struct field by field (default tolerance `1e-12`), rather than just checking that each runs without crashing. See [`tests/README.md`](tests/README.md).
- `addSoftwareStamp.m` (all three folders) - extracted out of `export_pub_fig.m` (previously a private local function there) into its own file, so `MIDAS_Main.m`'s movie-writing code can call it too: every GIF frame and `_movie_t*.jpg` now carries the same "MIDAS - Stroh & Moulas (2026)" attribution as PDF/PNG exports already did. Closes the gap where a GIF or movie JPG pulled out of context had no way to trace back to the software that made it (`.mat`/`.xlsx` exports already carried `R.software` - see Corrected below).
- `validateCoreParams` (new local function in `MIDAS_Main.m`, all three folders, called at the very top) - fails fast with one precise, plain-language message per problem field (naming the field, its actual value, and why it matters) for `CFL`, `t_tot`, `lxA`, `lxB_factor`, `nx_A`, `nx_B`, `DRG`/`DRG_LuHf`/`DRG_Mn`/`DamA`/`DamB`. Checks are NaN-safe (`~(x > 0)` rather than `x <= 0`), since a NaN - e.g. from a GUI numeric field that got non-numeric text - silently passes any `<=`/`<`/`>=` comparison.
- A guard in the `eqMode = 'poly'` branch of `MIDAS_Main.m` (all three folders): errors clearly, naming the exact problem and two concrete fixes, if `Tar`/`Par`/`Car_G`/`Car_B` still contain their `MIDAS_Params.m` `[NaN,NaN,NaN]` placeholders - instead of silently fitting a polynomial to NaN and producing a finite-looking but scientifically meaningless result (see Fixed below).
- **Close Figs** button (both GUIs, next to Run/Reset) - closes every open figure window from any past run (not just the most recent one) without closing the app's own control window.
- `docs/gui.md`: new "Performance" subsection under Octave GUI, explaining why its live-updating plot is slower than the MATLAB GUI's (the `tiledlayout`/`nexttile` shim rebuilds all 8 panel axes from scratch on every redraw, compounded by the `fltk`/`gnuplot`-only graphics toolkit available on this Windows install) and recommending the MATLAB GUI when a license is available, with `recordDT` as the cheapest workaround in the meantime. Cross-linked from `docs/octave.md`'s existing MATLAB-recommendation note.
- Documentation images - the docs site had no figures at all outside `examples.md`; added five:
  - `docs/index.md`: a new conceptual schematic (`docs/assets/diagrams/model_schematic.svg`) of the moving-boundary domain - phase A/B, interface `S(t)`, and the shared diffusion profile `C(x,t)`.
  - `docs/equations.md`: a second, symbol-annotated variant of the same schematic (`model_schematic_equations.svg`), labeled with the page's own notation (`D^A`, `D^B`, `L = l_A + l_B`, `Da_A`/`Da_B`, `k^A`/`k^B`, `K_D`).
  - `docs/mesh-refinement.md`: a real grid-convergence plot for `Example1_Baseline`, 15 resolutions from `nx_A = nx_B = 15` to `300`, densely sampled around the transition - shows a sharp threshold between `nx=150` and `nx=160` (not a loose "150-200" range - an initial coarser 7-point sweep placed it there, but finer sampling pinned it down precisely), with genuinely erratic (not just off) diagnostics below threshold and a flat, stable plateau from `nx=160` through `300`. The shipped default of `nx=200` sits safely inside that plateau.
  - `docs/phase-diagrams.md`: a standalone contourf render of the shipped `Pelite_avg_1.dat` table (column 7, MgO in phase A) across its full P-T range.
  - `docs/gui.md`: a real screenshot of the MATLAB GUI (`GUI/MIDAS.m`), captured via a Win32 screen-region grab since MATLAB App Designer's composited uifigure doesn't respond to `PrintWindow`, then cropped to remove desktop/taskbar bleed from the capture rect. An equivalent Octave GUI screenshot was attempted but not obtained - `PrintWindow` returns a solid black frame for Octave's `fltk`-rendered window (the renderer doesn't support it), and screen-region capture couldn't locate the window correctly across this machine's two-monitor layout; left for a follow-up or a manually-supplied screenshot.
  - A sixth, a `plot_misfit(R)` output for `docs/interpreting-output.md`, was tried and then deliberately not included: it incidentally surfaced that the isochron-age misfit (not the apparent-age misfit) spikes sharply late in the relaxation window on both examples checked, consistent with the isochron regression becoming ill-conditioned as reference/profile compositions converge. Author's call: not confident this diagnostic gives reliable/needed results and doesn't use it, so it shouldn't be presented as endorsed in the official docs - the table row mentioning `plot_misfit.m` stays (factual pointer, not a figure/endorsement).
- `docs/octave.md`: new "Performance" section, measured (not estimated) on this machine - `Example1_Baseline` at full resolution, `doPlot = false` (pure numerics): originally 48.2 s under MATLAB vs. 1040.5 s under Octave before the `thomasSolve` fix below (~21.6x slower; `Example3_ThermalBump`'s equivalent Octave run never finished either before or after the fix - stopped after 12+ minutes both times - so no ratio is reported for it). Traced to `thomasSolve` (`MIDAS_Main.m`'s hand-written tridiagonal solver): 61% of total runtime in a shorter profiled run (42/69 s, 6,360 calls), consistent with MATLAB's JIT compiling its tight scalar loop efficiently while Octave's interpreter does not. Cross-linked with the existing GUI-performance note.

### Removed

- `'interpreter','latex'` (and `$`-delimited LaTeX math mode) across every plotting file in `octave/` - Octave's LaTeX renderer fails its own startup self-test on this install and disables itself (see Known limitations below), so every `'latex'`-interpreted label was showing raw markup verbatim (`$^{176}$Hf`, `$\Delta T$`, literal dollar signs) instead of being typeset - confirmed visually by rendering a real figure to PNG and inspecting it. Removed the interpreter argument entirely (now defaults to Octave's `'tex'` interpreter) and stripped `$` delimiters from every label string; backslash commands the codebase actually uses (`\Delta`, `\tau`, `\max`, `^{...}`, `_{...}`, `^o`) all render correctly under plain `'tex'` with no changes needed - confirmed by direct visual comparison (Greek letters, super/subscripts, and the degree symbol all render correctly; `\%` does not - `'tex'` doesn't recognize that LaTeX-specific escape, so it was separately unescaped to a plain `%` everywhere it appeared). As a side effect, this also fixed the y-axis tick labels themselves appearing mirrored/corrupted, which turned out to be a knock-on effect of the same broken LaTeX renderer state rather than a separate bug. Scoped to `octave/` only - MATLAB's LaTeX rendering isn't affected by this Octave-specific issue, so `matlab/`/`GUI/` keep `'latex'` throughout, unchanged.

- `plot_massbalance.m`, `plot_Lu_profile.m`, `plot_Mn_profile.m`, and `plot_initial_conditions.m` (all three folders) moved to a developer-only local stash, not part of the public repo - fewer figures shown/exported by default (`Run_MIDAS.m` and both GUIs no longer call them). `plot_velocity_age.m` similarly trimmed from 6 outputs to 2 (`figRelErrLog`, `figABOnly`); the dropped 4 (`figAB`, `figErr`, `figRelErr`, `figErrLog`) and the full original file also moved to the same stash.
- `plot_misfit.m` (all three folders) dropped from the default plotting pipeline - `Run_MIDAS.m` no longer calls it (and its `save_misfit` flag is gone), neither GUI calls it from their post-run figure list (`GUI/MIDAS.m`'s progress dialog step count adjusted 7->6 accordingly), and `.github/scripts/smoke_test.m` no longer exercises it. Author's call: not confident the isochron-age misfit curve it plots gives reliable/needed results and doesn't use this diagnostic (see also its image being pulled from `docs/interpreting-output.md`, above). The file itself still exists - moved to `dev/<folder>/plotting/plot_misfit.m` (the same gitignored, developer-only stash as the four files above), not deleted outright, so it's still available to run manually (`plot_misfit(R)` still works if you add that folder to your path). `R.misfitApparentH`/`R.misfitIsochronH`/`R.misfitApparent_final`/etc. are untouched - only the plotting function moved, not the underlying data MIDAS_Main computes. Doc references updated to match: `docs/api-reference.md`'s plotting-functions table, `docs/interpreting-output.md` (prose + the "which plot answers which question" table), and `docs/equations.md`'s inline mention.

### Fixed

- `matlab/MIDAS_Main.m`: the Mn boundary-condition line inside the main time-stepping loop, `KDMn = KDMnFun(T,P)`, was missing its trailing semicolon - echoed `KDMn`'s value to the console on every single iteration of every run. `GUI/MIDAS_Main.m` and `octave/MIDAS_Main.m` already had the semicolon; matlab's copy is now fixed to match. Scanned all three folders' `MIDAS_Main.m`/`MIDAS_Params.m`/`Run_MIDAS.m`/examples/plotting/export files for the same pattern (an assignment with no trailing `;` and no line-continuation) - no other instances found.
- `matlab/MIDAS_Main.m`: the `PTmode` inline comment said "explicit T peak/P peak" (stray spaces) instead of "explicit Tpeak/Ppeak" - inconsistent with the same comment everywhere else (`MIDAS_Params.m` and all six examples, all three folders) and with the actual variable names used in the `'peak'` case just below it.
- `export_pub_fig.m` (all three folders): the GUI's Export Figures button could fail with `exportgraphics ... Cannot create output file`, reproduced on unrelated figures always at the same point (the 3rd/4th write in a batch, i.e. the `_notitle` variants) - consistent with a cloud-sync client (OneDrive, etc.) briefly locking the just-written file on a synced folder, not a bug in any one figure. `exportgraphics` is now retried up to 3 times (0.3 s apart) before giving up (Octave falls back to `print()` after, as it already did). Both GUIs' Export Figures loop also now catches a per-figure export failure and continues with the rest instead of aborting the whole batch, and both GUIs now populate the Export Data/Figures folder fields with an absolute path after a run instead of one relative to `pwd` at run time, which could silently resolve elsewhere if `pwd` shifted before Export was clicked (a folder-browse dialog can do this).
- `GUI/MIDAS.m`: every button's callback was registered as `createCallbackFcn(app, @app.XButtonPushed, true)` - since `@app.XButtonPushed` is already a bound method handle, the `true` flag made `createCallbackFcn` prepend `app` a second time, so clicking *any* button (Run, Reset, Load Example, Save/Load Preset, Export, Browse, Refresh/Delete Results, the now-removed theme toggle - all 13) failed with `Too many input arguments`. Fixed to the standard App Designer `@XButtonPushed` (unbound) form.
- **Adversarial/beginner-mistake testing pass** (both a programmer trying edge cases, and a non-programmer domain scientist fat-fingering values) surfaced several real correctness/usability bugs, now fixed and verified in `octave/` (mirrored, but not execution-verified, in `matlab/`/`GUI/`):
  - `params.CFL <= 0` (most notably `CFL = 0`, an easy typo) made the adaptive time step `dt = 0` - the run never advanced and hung forever with no error and no output. Now caught by `validateCoreParams` (see Added) before the run starts.
  - A missing/misnamed `params.PD` phase-diagram file correctly triggers `MIDAS_Main`'s existing `eqMode: 'PD' → 'poly'` fallback, but that fallback then used the default `MIDAS_Params()`'s `Tar`/`Par`/`Car_G`/`Car_B` - which are `[NaN,NaN,NaN]` placeholders, only ever meant to be set when `eqMode = 'poly'` is chosen deliberately (see e.g. `examples/Example2_PolyEquilibrium.m`). Fitting a polynomial to NaN produced a singular-matrix warning on the first call, which then propagated into `isochronsRef` calling `polyfit` on degenerate data on nearly every timestep - **17,553 lines of warnings for a 1 Myr test run** - while `R.S_final` stayed finite and plausible-looking even though `R.CA_final`/`CB_final`/`tALuHf1_final` correctly came out `NaN`. Since `.github/scripts/smoke_test.m`'s only pass criterion was `isfinite(R.S_final)`, this exact failure mode would not have been caught by CI. Now caught explicitly (see Added); `smoke_test.m` was also hardened to check `CA_final`/`CB_final`/`tALuHf1_final` for NaN, not just `S_final`.
  - `octave/MIDAS_GUI.m`'s numeric fields are plain text `uicontrol`s (Octave has no native numeric-only edit field like MATLAB's `uieditfield(...,'numeric')`), so non-numeric text typed into one produced `NaN` via `str2double`, which then silently passed every one of `validateParams`'s `<=`/`<` guard checks (`NaN <= 0` is `false`) straight through to `MIDAS_Main`. Both GUIs' `validateParams` now use the same NaN-safe comparison pattern as `validateCoreParams`.
- `octave/` port: verified for the first time by actually running it under a real Octave interpreter (11.3.0) rather than logic-checking against MATLAB only, surfacing and fixing several real bugs:
  - `griddedInterpolant` (used for the P-T path lookup in `MIDAS_Main.m`) does not exist in Octave at all - replaced with `interp1(...,'extrap')` anonymous functions.
  - `tiledlayout`/`nexttile` do not exist in Octave either, contrary to this port's own `octave/README.md` claim that Octave 7.1+/8.x has them - added `octave/tiledlayout.m` and `octave/nexttile.m` as drop-in shims (backed by `subplot`), so the 7 affected plotting scripts needed no changes.
  - MATLAB-style dot-notation property access on graphics handles (`cb.Label.Interpreter = ...`, `lgd.FontSize = ...`, `titles.handles(i).String = ...`) throws `scalar cannot be indexed with .` in Octave - converted to `get`/`set` calls across `plot_them_1.m`, `plot_them_3.m`, `plot_velocity_age.m`, `MIDAS_Main.m`, `export_pub_fig.m`.
  - `round(x,n)` (MATLAB's two-argument, round-to-n-decimals form) isn't supported by this Octave's `round` - replaced with `round(x*10^n)/10^n` in `plot_them_2.m`/`plot_them_3.m`.
  - The new `tiledlayout.m` shim didn't clear previously-drawn axes on repeated calls the way MATLAB's real `tiledlayout` wholesale-replaces its layout every call - `subplot`-reused axes silently carried over prior lines/legend entries/annotations, accumulating them frame-over-frame during a live-updating run (visible as a growing legend and cluttered/overlapping panels). Now deletes existing axes first.
  - The new `nexttile.m` shim always returned its axes handle regardless of `nargout`, unlike MATLAB's real `nexttile` (which only assigns a return value when the caller asks for one) - caused `ans = ...` to spam the console on every bare `nexttile(n)` call. Fixed to check `nargout`.
- Faure & Mensing's *Isotopes: Principles And Applications* (3rd ed., WILEY) was cited with the year 2025 everywhere it appears - the real publication year is 2005. Fixed across 23 files: `docs/references.md`, `docs/equations.md` (two inline citations plus the reference-list entry), and the `HfiBref` inline comment in `MIDAS_Params.m` and all six example files, in all three of `matlab/`, `GUI/`, `octave/`.
- `docs/assets/diagrams/model_schematic.svg` and `model_schematic_equations.svg`: the concentration-profile curve was drawn as one smooth, continuous line across the interface - scientifically wrong, since $K_D = C_A^{int}/C_B^{int}$ (`docs/equations.md`) means the concentration is generally *discontinuous* there (a jump, not a kink), matching how `plotAB.m` itself always plots phase A and B as two separate lines. Redrawn as two distinct curves (colored to match each phase, not meeting at the interface). Also fixed in `model_schematic.svg`: the `S(t)` interface label overlapped the "Moving-boundary domain" title above it; repositioned into the gap between the title and the domain box (and, in passing, the curve's inflection point in `model_schematic_equations.svg` wasn't sitting exactly on the interface line - now centered on it). `model_schematic.svg`'s "Fe-Mg diffusion" label (next to the flux arrows) was also removed - Mg-Fe is only the major-element example this repo uses throughout; the schematic itself is meant to read as the general phase-A/B model, not tied to one specific element pair.
- `docs/references.md`: the Stroh, Aellig & Moulas (2026) GMD citation was missing its year and had a stray, out-of-place "1." where the year should have been (a leftover editing artifact) - `docs/equations.md` and `README.md` already had this citation correctly formatted; `docs/references.md` is now consistent with both.
- `docs/assets/examples/midas_example1_baseline.gif` and `midas_example6_cylindrical.gif`: regenerated from the current (unmodified) `matlab/` plotting code. The previous files were comparatively tiny (560x420, 7 frames, ~100-130 KB) in a way the current default parameters don't reproduce on this machine - likely made with a different `recordDT`/capture setup not recorded anywhere. Regenerated at this machine's native capture resolution (1750x1260, a display-scaling artifact, not a code change) with `recordDT = 2.5` (vs. the example's default `0.5`) to keep frame count - and so file size and generation time - reasonable: 15 frames, ~1.1 MB each, matching the content/style of the previous files otherwise unchanged.
- `docs/assets/screenshots/gui_matlab.png`: cropped - the original Win32 screen-region capture included a sliver of desktop wallpaper on the left edge and the Windows taskbar along the bottom (both outside the actual window bounds the capture rect reported); now tightly cropped to the window content only.
- `docs/assets/figures/mesh_convergence.png` and `phase_diagram_example.png`: regenerated without the "MIDAS - Stroh & Moulas (2026)" software-attribution stamp `export_pub_fig.m` adds automatically - both are custom analysis scripts (a resolution sweep across 7 separate runs; a standalone replot of the raw phase-diagram table), not output from any actual `MIDAS_Main`/`plot_*.m` function, so the attribution was misleading there. `apparent_age_misfit.png` keeps its stamp - that one genuinely is `plot_misfit(R)`, a real MIDAS plotting function.
- MIDAS's own self-description, repeated near-identically in `CITATION.cff`, `README.md`, `docs/index.md`, and the header comments of `MIDAS_Main.m`/`MIDAS_Params.m`/`Run_MIDAS.m` (all three folders - 11 files total), called it "an interface-limited crystal-growth model." Per `docs/equations.md`'s own explanation, interface-limited (`Da << 1`) is only one end of the Damköhler spectrum the model can represent - the *other* end is diffusion-limited (`Da >> 1`), and the shipped defaults (`DamA = DamB = 1e3`) actually sit deep in that diffusion-limited regime, not the interface-limited one the blanket description implied. Reworded everywhere to "couples interface kinetics and diffusion across an explicit moving boundary (a Stefan/moving-boundary problem)," which doesn't assert a regime; `docs/equations.md`'s own explanatory passage (which correctly calls interface-limited "the model's namesake case," one regime among several) was left unchanged. Added "isochron ages" alongside "apparent ages" in the same sentences while editing them, since the model computes both but only apparent ages were previously named. Also fixed in `MIDAS_Params.m` (all three folders): the same header listed "Mg-Fe-Mn major elements + Lu/Hf/Mn trace elements" - Mn in both groups at once, the same bug as the `docs/index.md` one above, fixed the same way (Mn is trace-only; `MIDAS_Main.m`'s header already had this right).
- `MIDAS_Params.m`'s default `lxA` (all three folders): `0.5` -> `0.8`. User reported the figures from a plain `MIDAS_Params()` run "looked completely different" from the paper (Stroh, Aellig & Moulas, 2025). Checked the full git history first (`git diff` across every recorded commit of `matlab/MIDAS_Params.m`) - confirmed no numeric default has ever actually changed, only comments/whitespace, ruling out a regression. Compared the paper's published parameter tables (Appendix, Tables A3-A7) against the current defaults directly: everything else already matches (P-T path, thermodynamics, grid, `KDLu`/`KDHf`, trace-element initial contents, etc.), `DamA`/`DamB` already matches the paper's "Diffusion-limited regime" column (`1e3`; the paper's other column, "Reaction-limited," uses `0.1`), but `lxA` matched neither paper column (both list `0.8`; the repo had `0.5`) - fixed to `0.8`. Re-verified cross-implementation parity (`tests/compare_results.m`) after the change - all six examples still agree within the documented `1e-9` tolerance across `matlab`/`GUI`/`octave`.
- `isochronsRef` (`MIDAS_Main.m`, all three folders): `isoNskip = NaN` - the paper's own table value, and the natural "unused" placeholder this codebase uses everywhere else (`Tar`/`Par`/`Car_G`/`Car_B`, etc.) - crashed with `Array indices must be positive integers or logical values` (`idx = 1:nskip:numel(CPA)` does not reliably evaluate to an empty range for a `NaN` step, contrary to an initial assumption that wasn't actually tested first). Fixed properly: `idx` is now built only when `isfinite(nskip) && nskip >= 1`, otherwise set to `[]` directly, so the "every-nskip-th-node" profile sampling cleanly contributes nothing (matching `isoShowProfile = 0`, which already means these extra points aren't shown) instead of crashing. Verified with a real run (`isoNskip = NaN`, both `matlab/` and `octave/`) before trusting it. `MIDAS_Params.m`'s default (all three folders) restored to `NaN`, matching the paper; the six `examples/*.m` files keep `isoNskip = 10` (the paper's tables only cover `MIDAS_Params.m`, and `10` was never broken - only `NaN` was).
- `docs/references.md`: the "MIDAS itself" section listed the software citation and the GMD methods paper it builds on back-to-back with no distinction, reading like two citations for the same thing. Split into "Citing the software" and "Numerical method MIDAS builds on" subsections. `README.md` and `docs/equations.md` already kept these separate naturally - only `docs/references.md` needed the fix.

### Known limitations

- This Windows Octave install - checked for both the `winget install GNU.Octave` package and the official `octave.org` 11.3.0 Windows installer, which produced an identical result - ships only the `fltk` and `gnuplot` graphics toolkits; `qt` (the toolkit Octave's own runtime warnings recommend, and normally the default on other platforms) is unavailable (`available_graphics_toolkits()` never lists it, and no Qt DLLs exist anywhere under the install tree). `print()`/`exportgraphics` always route through `fltk` for rasterization regardless of which toolkit is set active.
  - LaTeX label rendering failing its own startup self-test is now worked around (see Removed above) rather than left broken - `octave/` no longer requests the `'latex'` interpreter anywhere.
  - Exporting any figure with 2-D color-mapped content (`print()`/`exportgraphics` to PNG/PDF) still hangs indefinitely (`GL2PS warning: Unknown token in buffer`, then no further progress) - confirmed this is **not** specific to `contourf`: `pcolor` and `imagesc` were both tested as potential substitutes and hang identically. This is a broader `fltk`/GL2PS limitation affecting any rasterized/shaded 2-D content, not something a different plotting function choice can route around; still unresolved, still needs a working `qt` toolkit. Avoid `saveCheckpoints`/figure export for the phase-diagram panels (or any color-mapped plot) under Octave on Windows until then.
- `docs/octave.md` states `ci-octave.yml` "exercises [the port] under a real Octave interpreter on every push," but `.github/scripts/smoke_test.m` sets `doPlot = false` throughout, so it never actually exercises `MIDAS_Main.m`'s own live-plotting branch (where the `griddedInterpolant` bug above lived). It does call `plot_velocity_age.m` and other standalone plotting functions directly, which use `tiledlayout` and should fail on any genuine Octave install (which has never had `tiledlayout` built in) - whether that CI job has actually been passing or failing was not confirmed here.
- `octave/MIDAS_GUI.m`: in a non-interactive batch test, closing its window (many nested panels/controls) crashed the Octave process during cleanup on the `fltk` toolkit - consistent with the other `fltk` limitations above rather than a bug in the GUI's own logic, but not yet confirmed either way against closing the window normally in an interactive session. Report back if this reproduces interactively.
- `.github/scripts/smoke_test.m`'s full pipeline had never actually been run to completion under Octave before now - running it end-to-end surfaced (and fixed) four more real Octave-compatibility bugs beyond the ones already listed above:
  - `legend('Location','best', ...)` was originally suspected as the trigger for a hard crash deep inside Octave's own `legend.m` (`kids(1): out of bound 0 (dimensions are 0x0)`, from `legend>create_item`) in `plot_massbalance.m`. Changing the location to `'northeast'` alone did **not** fix it - isolated repros narrowed the real cause down to `yline(0,'Color',[0.7 0.7 0.7],'HandleVisibility','off')` on the same axes: a plain `yline(0,'--')` (no `HandleVisibility`) followed by `legend(...)` is fine, but adding `'HandleVisibility','off'` to it crashes `legend()` outright, regardless of the requested location. Fixed in `plot_massbalance.m` by replacing that `yline` with an equivalent `plot(xlim,[0 0],...,'HandleVisibility','off')` (avoids `yline` entirely); `plot_misfit.m`/`plot_massbalance.m`'s legend locations were changed to `'northeast'` while investigating and left there (harmless, already verified working) rather than reverted back to `'best'`.
  - `params.make_movie = 1` had never actually worked under Octave at all, independent of the toolkit issues above: `[imind,cm] = rgb2ind(im,256)` (MATLAB's image-plus-colorcount calling form) isn't a valid Octave signature (`Invalid call to rgb2ind`). Fixed by dropping the second argument (`rgb2ind(im)`) - 256 was already GIF's own hard maximum and MATLAB's own default when omitted, so this changes nothing about the output on either platform. Applied in `octave/MIDAS_Main.m` only (the bug is Octave-specific; not yet confirmed whether the two-argument form is valid under real MATLAB, so `matlab/`/`GUI/` were left as-is).
  - `parula(n)` (used to colormap several fixed-position/time-series line plots) doesn't exist in Octave at all - replaced with `viridis(n)`, Octave's own closest perceptually-uniform equivalent (a plain callable function there, unlike in MATLAB), in `plot_age_at_fixed_positions.m`, `plot_conc_at_fixed_positions.m`, `plot_age_vs_temperature.m` (`octave/` only - `parula` exists natively in MATLAB, so `matlab/`/`GUI/` are unaffected and unchanged).
  - `sgtitle(...)` (the whole-figure title in `plot_initial_conditions.m`) doesn't exist in Octave either - added an `exist('sgtitle',...)` check that falls back to an `annotation('textbox',...)` spanning the top of the figure when it's unavailable, matching a pattern `export_pub_fig.m` already used defensively for the same reason. Note: unlike a real `sgtitle`, this fallback annotation isn't picked up by `export_pub_fig.m`'s title-hiding logic, so it still shows in the `_notitle` exported variant - a minor cosmetic gap, not fixed here.

## [0.1.0] - 2026-08-28

Initial version.

### Added

- Three independent, self-contained copies of the model: `matlab/` (command-line/scripts), `GUI/` (interactive MATLAB App Designer front-end, `MIDAS.m`), and `octave/` (GNU Octave port) - identical physics and identical default parameters across all three.
- Six standalone example configurations, under each folder's own `examples/` subfolder (`Example1_Baseline` through `Example6_CylindricalGeometry`), each a complete, self-contained parameter set with every field it doesn't use set to `NaN`, exercising every mode switch in the model. All six run to completion at full grid resolution with physically sensible (net-growth) results.
- GUI: **Load Example** dropdown + button - pick any of the six examples (or plain `MIDAS_Params`) and populate every field from it as a starting point; every field stays freely editable afterwards.
- Boundary conditions (`implicitDiffusionSolver.m`): the center of the domain (x=0) is always Neumann for cylindrical/spherical geometry (`ndim` = 2, 3), as required by symmetry, regardless of `NBC`; the outer edge of phase B always follows `NBC` freely (Neumann or Dirichlet), for every geometry.
- `plot_initial_conditions.m` - every element/isotope's initial ($t=0$) profile, phase A vs. phase B, one figure (the "before" to `plot_all_composition_profiles`'s "after").
- Figures export as a vector PDF + PNG, both a titled and an untitled version, with a small attribution stamp (`export_pub_fig.m`). Nothing is written to disk by default otherwise - `save_data`, `make_movie`, and every per-figure `save_*` flag in `Run_MIDAS.m` start off; opt in per field.
- CI: `ci-matlab.yml`, `ci-gui.yml`, `ci-octave.yml` (smoke-test all six examples plus the full plotting/export pipeline on every push - `.github/scripts/smoke_test.m`), `docs.yml` (GitHub Pages), and `spellcheck.yml`.
- Full documentation site (`docs/`): getting started, examples, configuration options, equations/theory, mesh & time-step refinement, interpreting output, benchmarks, phase-diagram (Perplex) setup, references, API reference, GUI guide, and Octave notes - with the MIDAS logo (light/dark-aware) on every page.
- `LICENSE` (MIT), `CITATION.cff`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`.
